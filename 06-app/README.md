# labeled — Telegram Mini App

Спецификация — `../design_handoff_labeled_tma/README.md`, визуальный референс — кадры `*.dc.html` в той же папке.

## Запуск

Node 24 установлен в `~/.local/node` (в PATH оболочки не добавлен):

```sh
export PATH=~/.local/node/bin:$PATH
npm install
npm run dev        # http://localhost:5173 — окружение Telegram подменено демо-данными
npm run build      # проверка типов и сборка в dist/
npm run preview    # собранная версия; без Telegram откроется экран BB, с ?demo — приложение
```

### С сервером (07-server)

Без `VITE_API_URL` приложение работает на моках — так сверяются кадры, работают `?scenario=…` и все скрипты ниже. С `VITE_API_URL` те же экраны ходят на сервер:

```sh
# 1. сервер с демо-данными (см. ../07-server/README.md)
(cd ../07-server && npm run build && SEED_DEMO=1 PGLITE_DIR=/tmp/lbd-pg CORS_ORIGIN=http://127.0.0.1:5174 node dist/main.js) &
# 2. приложение с сервером на отдельном порту
VITE_API_URL=http://localhost:8787 npx vite --port 5174 --host 127.0.0.1
# 3. сквозная проверка на свежей базе: покупатель ↔ админка через сервер
BASE=http://127.0.0.1:5174/ node scripts/check-live.mjs
```

- В Telegram запросы несут `Authorization: tma <initData>`; в браузере с `?demo`/в разработке — `x-dev-user` с id демо-пользователя (сервер принимает его только вне production). Анна — 1001; `?staff=owner|manager|stock|content` входит сотрудником из демо-данных сервера: Иван 2001, Ксения 2011, Артём 2012, Лиза 2013.
- Запуск (BA): `/api/system` (техработы, версия), справочники (курс, реквизиты, категории), вход. Новый пользователь без согласия → гость (E), согласие на экране P.
- После входа с сервера грузятся баллы, имя, почта, уведомления, адреса, избранное, платежи, черновики, непрочитанные события (`src/api/session.ts`). Корзина хранится на устройстве (`localStorage`).
- Локальные изменения уведомлений, избранного и черновиков уходят на сервер через `remote` в `src/store/app.ts` (заполняет `src/api/live.ts`).
- Админка: экраны грузят свой раздел (`adminLoad`, хук `useLoad`), действия идут на сервер и перечитывают раздел; очередь задач и сводку считает сервер.
- Демо-кнопки, изображающие продавца («Показать ответ продавца», «Вариант ответа», «Показать: продавец перевёл», «Подтвердить (демонстрация)», роли в «Ещё»), с сервером скрыты.

Режимы адресной строки (моки):
- `?demo` — демо-окружение Telegram в собранной версии;
- `?path=/pay/p-1042-1` — в демо открыть экран сразу (для показа и сверки); «Мои заказы» открываются из профиля;
- `?scenario=price` / `sold` / `uploaderr` / `calcerr` / `searcherr` — ответ сервера: цена изменилась (A), вещь продана (L), чек не загрузился, курс недоступен (B), поиск не работает;
- `?scenario=booterr` / `maint` / `update` — запуск: вход не подтверждён за 8 секунд (BA), техработы и устаревшая версия (AH);
- `?scenario=noorders` — покупатель без заказов (AY);
- `?onboarding` — знакомство с сервисом (AD → AE) в демо;
- `?start=ref_1001` / `item_tee` / `order_1042` — параметр запуска Mini App в демо;
- `?guest` — демо гостя: вход ещё не выполнен (E, P);
- `?offline` — все запросы падают (состояние «Нет соединения», кадр Q);
- `?staff=owner` / `manager` / `stock` / `content` — демо-сессия сотрудника (Иван Петров с выбранной ролью): в профиле появляется «Режим работы», режим администратора — `?staff=owner&path=/admin`.

В демо есть кнопки, которых нет в Telegram: «Показать ответ продавца», «Вариант ответа», «Показать: продавец перевёл», «Подтвердить (демонстрация)».

Переменные: `VITE_BOT_LINK` — ссылка на Mini App (`https://t.me/<бот>/app`) для BB, приглашений и «Поделиться»; `VITE_SUPPORT_BOT` — аккаунт поддержки; без неё — заглушка `@your_support` (константа в `src/ui/support.ts`). Для человека ссылка `t.me/<имя>?text=…` подставляет сообщение с номером заказа, для бота (имя на «bot») номер уходит в `/start order_<номер>`; `VITE_YANDEX_MAPS_URL` — карточка labeled в Яндекс Картах (AB).

## Сверка с макетами

```sh
(cd ../design_handoff_labeled_tma && python3 -m http.server 8901) &
npm run dev &
node scripts/shots.mjs /tmp/shots "mock:Labeled Flow v12:7a" app:7a
```

`mock:<файл>:<кадр>` снимает кадр макета, `app:<сценарий>` — то же состояние приложения в 390×844. Сценарии описаны в `scripts/shots.mjs`. Нужен Chromium: `npx playwright install chromium`.

В zsh имя файла с пробелами передавайте через `"mock:${B}:V"`, а не `$B:V` (zsh читает `:V` как модификатор). `shots.mjs` печатает `ERR <задание> …` при ошибках в консоли приложения.

Общий прогон: снять все кадры макетов и состояния приложения, затем собрать сводные листы «макет | приложение»:

```sh
node scripts/shots.mjs /tmp/all "mock:Labeled Buyer v15:V" app:V …   # кадры из макетов, сценарии из APP в shots.mjs
node scripts/sheet.mjs /tmp/all /tmp/sheets 4 7a 7r U BC …          # 4 кадра на лист
node scripts/check-after.mjs                                         # сценарии захода 3, код выхода 1 при ошибке
node scripts/check-admin.mjs                                         # сценарии админки и что после действий видит покупатель
```

Кадры админки: `node scripts/shots.mjs /tmp/adm "mock:Labeled Admin:adm04" app:adm04` (сценарии adm01–adm27, adm33, adm34 в `shots.mjs`; adm28–adm32 сверены вручную).
Контраст заголовка на баннере с фото: `node scripts/check-banner-contrast.mjs` (белая картинка и при `PHOTO=<файл>` фото, 360 и 390 px; нужно ≥ 4.5:1).

Кадры покупателя — в `Labeled Flow v12` (7a–7r) и `Labeled Buyer v15` (A–BF); `Labeled - все экраны` их повторяет, `Labeled Admin` — админка.

## Подводные камни

- Рабочая сборка — `../07-server/deploy/deploy.sh` (адрес API и `VITE_*` из `~/labeled-secrets.env`), не `npm run build` вручную.
- На телефоне (`ios`, `android`, `android_x`) приложение запрашивает полноэкранный режим (`bootTelegram` в `src/telegram/tma.ts`): шапки и закреплённые блоки сдвигайте на `var(--safe-top)` — в нём отступ под плавающие кнопки Telegram.
- `isTMA()` после перезагрузки страницы в браузере находит параметры, сохранённые демо-режимом в `sessionStorage`, и принимает браузер за Telegram. Окружение определяется сначала по `insideTelegramClient()` (`src/telegram/tma.ts`).
- `retrieveLaunchParams(true)` в SDK v3 отдаёт поля в camelCase, и `user.photo_url` пропадает. Используется вызов без аргумента.
- Суммы форматирует `rub()` с NNBSP между разрядами и NBSP перед ₽ — с обычным тонким пробелом сумма переносится по строкам.
- Возврат к экрану восстанавливает прокрутку, только если данные берутся из кеша `useApi(fn, deps, cacheKey)`; без `cacheKey` экран успевает показать скелетон.
- Демо-кнопки («Показать ответ продавца», «Вариант ответа», «Показать: продавец перевёл», «Подтвердить (демонстрация)») скрыты при `tmaEnv() !== 'mock'`; новые демо-элементы делайте так же.
- Открытие по `?path=` или параметру запуска кладёт под экраном родителей из `parentOf` в `src/App.tsx`; новый экран добавляйте туда, иначе у него не будет «назад».
- Листы рендерятся внутри `ToastProvider` (порядок провайдеров в `Shell`): формы в листах админки сами вызывают тост. Не меняйте порядок обратно.
- Селектор `useAdmin`/`useApp` должен возвращать примитив или ссылку из состояния: новый массив на каждый вызов зацикливает `useSyncExternalStore` (права считайте из `s.me` вне селектора).
- Действия админа идут через `adminApi` (`src/admin/api.ts`) с задержкой и журналом; очередь задач не хранится, а выводится из состояния (`buildTasks`). С сервером методы `adminApi` подменяются `liveApi`, очередь — с сервера.
- Справочники с сервера пишутся в те же объекты, что читают экраны: `RATES`, `REQUISITES`, `CATEGORIES` (`Object.assign`/`splice`). Не заменяйте их новыми объектами.
- CORS сервера должен разрешать PUT/PATCH/DELETE и заголовки `authorization`, `x-dev-user`.
- Запросы к серверу ограничены по времени (`src/api/client.ts`: 20 с, загрузка файла — 90 с); превышение — `ApiError('offline')`. Оформление и заявку можно повторить: ключ попытки (`useAttempt`) не даст создать второй заказ.
- Избранное, уведомления и черновики уходят на сервер через `syncLater` (`src/api/sync.ts`): по ключу одно последнее состояние, повтор при сбое сети. Новые «тихие» изменения делайте так же, не `.catch(() => {})`.
- Режим администратора — отдельный чанк: маршруты `/admin/*` в `src/admin/AdminRoutes.tsx`, подключены в `App.tsx` через `React.lazy`. Новый экран админки добавляйте туда. Покупательский код не должен импортировать `src/admin/screens/*` и `src/admin/ui.tsx` — иначе админка вернётся в основной файл (карточка профиля — `admin/StaffModeCard.tsx`).
- CSP рабочего сервера — `../07-server/deploy/security-headers.conf`; после сборки `node scripts/check-csp.mjs` проверяет экраны с этими заголовками. Внешние скрипты, шрифты и запросы к другим адресам CSP запрещает.
- Копирование в админке — `KV copy` (касание строки; `copyAs` — что копировать вместо подписи, `''` — строку не копировать; `copyAll` — «Скопировать всё»), `RowSpec.copy` и `useCopy` из `src/admin/ui.tsx`. Аватарки людей — `RowSpec.ava` / `Ava`, в журнале `RowSpec.subAva` (адрес с сервера через `fileUrl`, под фото значок — виден, если фото не загрузилось). В профиле покупателя значок тоже лежит под фото.
- Живое обновление заказов (с сервером): `src/api/changes.ts` держит поток `/api/live` и по сигналу увеличивает номер изменения; `useApi(…, { live: true })` и `useLoad(…, { live: true })` тихо перечитывают экран (без загрузки; неудача фонового обновления не показывает ошибку), платежи и баллы перечитываются в общем состоянии. Свёрнутое приложение поток закрывает и при возврате обновляет экран. Новый экран заказов подключайте опцией `live`; поля ввода держите в `useState`, а не копируйте из загруженных данных эффектом — иначе фоновое обновление их сотрёт. Поля платежа, которых нет на сервере (`fromCheckout`), `reloadPayments` переносит сам.
- Тост ошибки — `toast(текст, 'error')` (значок ошибки, 4 с); без второго аргумента — подтверждение с галочкой. Неактивная главная кнопка называет недостающий шаг. Второстепенный текст — `--lb-ink-3`, `--lb-mute` — только выключенное. Поля ввода не меньше 16 px (масштабирование страницы разрешено). Регрессия интерфейса — `node scripts/check-ux.mjs` (нужен `npm run dev`).
- Текст ошибки для тоста — `errorText(e, запасной текст)` из `src/api/client.ts`: «Нет соединения», 401/403, объяснение сервера на 400/409. Не сравнивайте `e.message` с кодом вручную: сервер отвечает кодами `no_permission`, `not_staff`, `owner_only`, а не `forbidden`.

## Устройство

- `src/telegram/tma.ts` — запуск SDK, демо-окружение, BackButton, цвет шапки, вибро.
- `src/nav/` — стек навигации поверх MemoryRouter: `go`, `back`, `root`, подпись «назад», перехват «назад».
- `src/ui/` — оболочка: шапка, экран, нижняя панель, нижняя навигация, листы, тосты, общие блоки.
- `src/domain/` — модели и правила: фильтр каталога, заказы, расчёт заказа по ссылке, обращения и возврат.
- `src/api/` — API-слой; сейчас отвечает данными из `src/mocks` с задержкой.
- `src/store/` — состояние покупателя (корзина, фильтр, баллы, избранное).
- `src/screens/` — экраны по блокам.
- `src/admin/` — режим администратора: модель ролей и прав (`model.ts`), API на моках с журналом (`api.ts`), блоки тёмной шапки и пристыкованной панели (`ui.tsx`), навигация (`AdminNav.tsx`), экраны adm01–adm34 (`screens/`). Демо-данные — `src/mocks/admin.ts`.
